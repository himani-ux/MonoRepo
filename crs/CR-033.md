# CR-033 - Simplify RCA Levels and Action Rationale

## What & why

Incident RCA should use only Immediate Cause and Root Cause in the current user-facing flow. The Intermediate Cause category should be removed completely from current RCA entry and display surfaces. Corrective and preventive action entry should also be simpler by removing the "Why is this needed?" field from corrective-action capture.

## Tier + triggers

Tier 3 - structural Maintain Mode change. Triggers: changed Incident Phase 2 RCA screen state, changed RCA validation/payload behavior, changed Incident Phase 3 corrective-action screen state, changed frontend payload behavior for hidden action rationale, and expected supersession of canonical RCA/action documentation that currently describes intermediate causes or corrective-action rationale as current user-facing fields.

## Domains touched

Step 1 domains to verify: Incident Phase 2 RCA UI/screen state, RCA cause-level taxonomy and validation, RCA payload compatibility, incident PDF/report RCA output, Incident Phase 3 corrective/preventive action UI, action payload compatibility, frontend regression tests, backend validation/serialization if applicable, and canonical safety documentation.

## Decisions

- `D-MAINT-CR033` - current Incident RCA uses Immediate Cause and Root Cause only. Intermediate Cause remains legacy compatibility only for existing stored data and is displayed under Root Cause instead of as a current category.
- Current corrective, preventive, and lesson capture does not show or submit "Why is this needed?" / recommendation rationale from the frontend.
