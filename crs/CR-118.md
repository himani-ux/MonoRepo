**What & why** - Class snapshot freshness must never be calculated from upload time. When the parser cannot read the class report's printed/generated date, office uploaders must enter the report date shown on the PDF so the system can store the true report date and run reconciliation without using an upload-date fallback.

**Tier + triggers** - Tier 2 small feature/behavior change. Triggers: changed validation rule, changed upload screen state, changed class snapshot upload contract handling, and new regression coverage.

**Domains touched** - Step 1 domains: class snapshot upload, class snapshot parser fallback, reconciliation freshness, vessel dashboard freshness display, frontend/backend API tests, and Certs documentation.

**Decisions** - D-CERT-205: Class snapshot freshness uses only the report date printed/generated on the PDF. The preferred path is parser extraction. If extraction cannot read the date, an office uploader may manually enter the same report date shown on the PDF. Upload date is never a freshness fallback. Accepted default: manual date is optional during normal upload, but required when the parser returns the readable-date failure.

Update `certs_docsuite/FIELD_MAP.md` to clarify `printed_on_date` is parser-derived or manually entered from the PDF, never upload-derived.
