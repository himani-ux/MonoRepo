**What & why**
Add a 50 MB maximum size validation for Circular PDF attachments so oversized uploads are rejected before storage and users receive a clear message.

**Tier + triggers**
Tier 2 - changed validation rule for Circular attachments.

**Domains touched**
Step 1 domain: Circular office create/upload flow; backend attachment intake; frontend attachment selection feedback; Circular user guidance.

**Decisions**
Accepted default: enforce 50 MB per attached PDF file on both frontend and backend. Existing PDF-only and maximum attachment-count behavior remains unchanged.

**Doc cascade**
- `Docs/SSOT_CIRCULAR_SEQUENCE_AND_PDF_ATTACHMENT.md` - added the 50 MB per-PDF attachment rule and backend/frontend enforcement references.
- `Docs/OFFICE_CIRCULAR_USER_GUIDE.md` - clarified that office users can attach up to 3 PDFs and each must be 50 MB or smaller.
- `Docs/modules/backend/circular.md` - documented backend rejection before storage for non-PDF, too many files, or PDFs over 50 MB.
- `Docs/modules/frontend/circular-workflow.md` - documented the browser-side 50 MB PDF guard in office authoring.
- `Docs/progress.txt` - recorded the Maintain Mode ledger entry.

**Tests**
- Backend regression added for oversized Circular PDF attachment rejection.
- Frontend source regression added to ensure both `Officeuser.jsx` and `Admin.jsx` keep the 50 MB guard.
- Passed: `python manage.py test modules.circular.circular_office.tests.CircularAttachmentValidationTests -v 2 --keepdb`

**Fidelity check**
SSOT, user guide, backend module notes, and frontend module notes all state the same rule: PDF only, maximum 3 files, 50 MB per PDF, with backend as final authority and frontend as convenience validation. No deltas.

None.
