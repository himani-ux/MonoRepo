**What & why**
External Audit registration no longer requires the user to select an External Audit Organisation. The field remains available when active organisations exist, but a user can register an external audit without it because the organisation may be unknown or not configured at registration time.

**Tier + triggers**
Tier 2 - changed validation rule and external audit registration request contract.

**Domains touched**
Domain 2 - External Audit registration screen state. Domain 7 - registration API validation/contract.

**Decisions**
Accepted default: keep the optional organisation dropdown visible when data is available, remove required UI copy, suppress the no-active-organisation blocking message, and submit an empty value as omitted/null rather than forcing a placeholder organisation.

**Doc cascade**
`audit_docsuite/USER_GUIDE.md` - states External Audit Organisation is optional and no configured organisations do not block registration.
`audit_docsuite/TEST_PLAN.md` - updates F-01C so the no-organisation state still permits registration.
`audit_docsuite/GAPS_2.md` - clarifies the master-data gap now affects exact organisation capture, not the ability to register.
`audit_docsuite/BACKEND_STRUCTURE.md` unchanged because no endpoint, permission, or table contract changed.

**Tests**
`psc-backend/tests/audit/test_registration_api.py` - added server-side coverage for registration without an organisation and kept RO-delegation defaulting coverage.
`psc-frontend/src/routes/audit/external/new.test.tsx` - updated the no-active-organisation UI case to assert registration succeeds.
`psc-frontend/src/lib/api/audit.test.ts` - added multipart payload coverage that blank organisation ids are omitted.

**Fidelity check**
