**What & why**
The uploaded KR Class Status PDF for EAST AYUTTHAYA contains visible class-status data from page 3 onward, but the data is stored as embedded page images with no PDF text layer. This change adds a bounded OCR fallback for class snapshot PDFs only when normal text extraction returns no text, so scanned/image-only KR/NK/BV class-status snapshots can still feed the existing parser and reconciliation workflow.

**Tier + triggers**
Tier 3 - structural. Triggers: contradicts the canonical D-CERT-048 statement that class snapshots are text-extract only, changes the parser contract for scanned/image-only PDFs, and extends OCR use from vessel-uploaded cert PDFs to class snapshot fallback.

**Domains touched**
Step 1 domains: Certs class snapshot parser, Certs OCR dependency usage, Certs reconciliation upload workflow, Certs backend/user documentation, Certs implementation plan decision surface.

**Decisions**
Accepted default: keep `pdfplumber` text extraction as the primary parser path and run OCR only when the full PDF exposes no text layer.

Accepted default: use existing local dependencies (`pytesseract`, `Pillow`, and embedded image extraction from the installed PDF stack) rather than adding a new OCR service, renderer, or dependency in this CR.

Accepted default: preserve the existing normalized parser payload and reconciliation engine contract. OCR fallback returns text to the same NK/KR/BV parser modules and marks the payload source/text-extraction engine as OCR fallback.

Accepted default: parser-anomaly notification dispatch is best-effort during reconciliation. If the shared `master_notification` table rejects Certs notification columns, the error is logged and the snapshot/reconciliation run still succeeds.
