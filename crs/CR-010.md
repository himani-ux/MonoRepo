**What & why**
Incident phase pages currently lock earlier phase edits as soon as `current_phase` advances. The requested behavior is that the incident remains editable across completed phases until office approval, so users can correct intake, office communication, root cause, evidence, and actions without a formal send-back before the office accepts the incident.

**Tier + triggers**
Tier 2. Triggered by changed validation rules and changed incident workflow editing behavior.

**Domains touched**
1. Incident phase edit validation
2. Incident phase API contracts
3. Incident workflow documentation
4. Incident regression tests

**Decisions**
1. Treat office approval lock as `state='APPROVED'`, `state='CLOSED'`, or `state='SUPERSEDED'`; RED-band DPA signature alone is not the final approval lock.
2. Allow phase edit endpoints for phases already reached while the incident remains pre-approval.
3. Keep submit/transition endpoints gated to their exact current phase so workflow advancement still follows the ordered phase state machine.

**Doc cascade**
- `safety_docsuite/APP_FLOW.md` - document that completed incident phases remain editable until office approval.
- `safety_docsuite/BACKEND_STRUCTURE.md` - document the incident edit-lock rule in the API contract section.
- `safety_docsuite/USER_GUIDE.md` - document that users can return to earlier phases before office approval.

**Tests**
Add backend regression coverage for editing an earlier phase after forward movement and rejecting the same edit after office approval.
