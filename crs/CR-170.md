**What & why**
Clean up External Audit registration so users attach/select the external audit PDF instead of manually typing technical report metadata such as file path and file size. The current backend registration contract still stores report file metadata, but the UI should derive that metadata from the selected PDF and keep technical fields out of the visible form.

**Tier + triggers**
Tier 2 - small feature / behavior change. Triggers: changed External Audit registration screen state, changed frontend validation behavior for report PDF capture, and widened the existing registration endpoint contract to accept multipart PDF upload for external audits.

**Domains touched**
Domain 2 screen/state coverage: Audit External Audit Registration (`SCR-AUD-8`).
Domain 7 field map / validation: external audit report attachment metadata (`FEAT-AUD-602`, `FEAT-AUD-603`).

**Decisions**
Accepted default: replace visible `Report File Path` and `Report File Size` inputs with one required PDF file attachment control.
Accepted default: keep the existing JSON metadata registration flow for backward compatibility, and add multipart `external_report_file` upload support for the user-facing External Audit form.
Accepted default: the backend saves the uploaded PDF under media storage and derives the stored file name, path, MIME type, and size from the uploaded file.
Accepted default: reject non-PDF selections in the UI before submit.
