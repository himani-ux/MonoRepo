# CR-016 - Simplify Phase 4 Witness Notes

## What & why

Phase 4 Witness Notes should be a short operational note form instead of a formal/informal interview workflow. The current user-facing form will keep only Witness name, What the witness said, and Closing note, reducing clutter while preserving the existing witness-interview API/table compatibility for stored records and older clients.

## Tier + triggers

Tier 3 - structural Maintain Mode change. Triggers: changed Safety screen state and client-side validation, and contradiction of canonical SSOT/PRD/APP_FLOW/USER_GUIDE/VALIDATION statements that described formal/informal interview controls and read-back/sign-off as current user-facing Phase 4 behavior.

## Domains touched

Step 1 domains to verify: Incident Phase 4 UI/screen state, witness interview evidence capture, client validation wording, legacy API compatibility, tests, and canonical safety documentation.

## Decisions

New SSOT decision `D-MAINT-CR016`: the current Phase 4 Witness Notes UI is simplified to three visible fields: Witness name, What the witness said, and Closing note. The UI submits notes as informal compatibility records with a system reason; backend formal/informal validation remains for API compatibility and older clients. This supersedes `D-DNV-08`, `D-GAP-R19`, and `D-GAP-R20` only for the current user-facing Phase 4 Witness Notes form.
