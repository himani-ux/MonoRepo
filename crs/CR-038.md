# CR-038 - Split incident actions into separate phases

## What & why
Separate Corrective Action, Preventive Action, and Lessons Learned into distinct incident workflow phases so users do not have to manage three different action types inside one combined screen. Remove the read-only Final Record phase from the visible workflow because it does not require user input, and simplify action entry by removing owner/checker fields, remaining-risk confirmation, and extra confirmation wording while keeping due date capture.

## Tier + triggers
Tier 3 - structural. Triggers: user-facing incident phase workflow changes, new/changed screen states, route/navigation behavior changes, and superseding the current canonical incident workflow that describes a combined Next Actions phase and visible Final Record phase.

## Domains touched
Step 1 Domains 2, 4, 5, 6, 7, and 8:
- Domain 2: incident screen states, phase tabs, and route navigation.
- Domain 4: workflow/status progression and role-facing review steps.
- Domain 5: validation and required/optional fields for action entry.
- Domain 6: API/data contract use for action records.
- Domain 7: field map for corrective/preventive/lesson data capture.
- Domain 8: test coverage for phase routing and action form simplification.

## Decisions
- D-MAINT-CR038-01 accepted default: use separate user-facing phases for Corrective Action, Preventive Action, and Lessons Learned while reusing the existing backend action storage contract where possible to avoid unnecessary data migration.
- D-MAINT-CR038-02 accepted default: remove Final Record only from the visible/editable workflow tabs; retain existing read-only final record route/API if it is required for audit, export, or direct legacy links.
- D-MAINT-CR038-03 accepted default: remove the "Who Will Do and Check This?" UI card from action entry screens and keep due date as the visible accountability field.
- D-MAINT-CR038-04 accepted default: remove Remaining risk and "I confirm this will reduce risk" from the Preventive Action user interface without changing stored historical records.
