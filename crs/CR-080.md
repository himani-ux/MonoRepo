**What & why** - The Safety Incidents register needed a vessel selector like the existing risk/status filters so office users can narrow the list by ship. The same screen also used confusing labels: `State` should read **Status**, and the risk-band column/filter should use **risk_band** instead of the old Band wording.

**Tier + triggers** - Tier 2. Triggers: new register screen state, new backend list-support endpoint for vessel filter options, and changed visible filter/table labels.

**Domains touched** - Step 1 domains: incident register/listing, vessel scoping, frontend filter UI, backend reference/list support, and maintain-mode documentation.

**Decisions** - D-MAINT-CR080: the current Incident register shows three filters: Vessel, risk_band, and Status. Vessel options come from active `VesselData` rows within the user's safety scope; global office users can select from all active ships. Selecting a vessel sends the existing incident-list `vessel_id` filter.

**Doc cascade** - `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` records D-MAINT-CR080 and documents the register filters. `safety_docsuite/APP_FLOW.md`, `safety_docsuite/PRD.md`, `safety_docsuite/USER_GUIDE.md`, `safety_docsuite/VALIDATION_RULES.md`, and `safety_docsuite/BACKEND_STRUCTURE.md` describe the current register filter labels and vessel option endpoint. `Docs/progress.txt` records the change.
