# CR-128

**What & why** - SCM attendance and WRH readiness should use the CMS crew status master to decide who is onboard. `Crew_Onboarding_History.CrewStatus` is the authoritative current crew-status UUID, so the attendance roster must include only rows whose `CrewStatus` master value is `On Board`.

**Tier + triggers** - Tier 2. Trigger: changed validation/eligibility rule for SCM attendance roster selection.

**Domains touched** - Safety SCM attendance; CMS crew roster integration; WRH host-readiness input roster.

**Decisions** - D-MAINT-CR128: For live CMS schemas, SCM attendance roster eligibility is based on `Crew_Onboarding_History.CrewStatus` joined to `CrewStatus.CrewStatusName = 'On Board'`; sign-on/sign-off dates are no longer the live-schema attendance eligibility check.

**Doc cascade** - `safety_docsuite/APP_FLOW.md` updated to state that SCM host readiness and attendance use the On Board CMS crew-status roster. `safety_docsuite/PRD.md` updated to state the same attendance source rule. `Docs/progress.txt` updated with this maintain entry. `Docs/BACKEND_STRUCTURE.md` unchanged because its active crew endpoint summary names only the source tables and does not define the live eligibility rule.

**Tests** - Added/updated CMS repository regression coverage that creates a live-style `Crew_Onboarding_History` and `CrewStatus` table, then verifies only `On Board` crew appear. Ran `python -m unittest tests.safety.test_cms_rank_at_date tests.safety.test_cms_live_join -v` successfully.

**Fidelity check** - no deltas

**Exemptions** - none
