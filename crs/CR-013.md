**What & why**
Incident evidence capture should be flexible from the start of the incident workflow. Users should be able to add Phase 4 evidence documents even when Phase 2 and Phase 3 are not completed, because evidence may be available immediately and should not be blocked by workflow sequencing.

**Tier + triggers**
Tier 3. Triggered by changed validation/workflow behavior, changed evidence screen availability, and superseding canonical documentation that previously described evidence editing as available only after the evidence phase was reached.

**Domains touched**
1. Incident evidence capture
2. Incident phase edit gates
3. Incident attachment upload
4. Incident workflow documentation

**Decisions**
1. Phase 4 evidence document endpoints are open to authorized incident editors before Phase 4 is reached.
2. Office approval, closure, superseded-state, vessel-scope, and role/permission locks still apply.
3. Ordered phase submit/transition rules remain intact; this change only makes evidence capture editable earlier.
4. The frontend must not redirect users back to Phase 2/root-cause when evidence is opened early.

- `safety_docsuite/APP_FLOW.md` - documented early evidence capture access and clarified ordered transitions still apply.
