# CR-043 - Renumber visible Incident phase labels sequentially

## What & why
The visible Incident workflow should not show a numbering gap after removing Lessons Learned. The user-facing phase cards and phase wording should read as a clean sequence: Phase 1 Report Incident, Phase 2 RCA, Phase 3 Corrective Action, Phase 4 Preventive Action, Phase 5 Add Evidence, Phase 6 Office Review, and Phase 7 Check Actions. Backend route names, persisted `current_phase` values, and API compatibility remain unchanged unless explicitly changed later.

## Tier + triggers
Tier 3 - structural. Triggers: changes documented user-facing workflow numbering and supersedes current SSOT/IMPLEMENTATION_PLAN statements that intentionally displayed Phase 6/7/8 after the removed Lessons Learned phase.

## Domains touched
Step 1 Domains 2, 5, and 8:
- Domain 2: visible incident phase map, tab labels, user training wording, and route-label compatibility notes.
- Domain 5: phase-transition wording must clarify that visible numbering is sequential while backend phase numbers remain compatibility identifiers.
- Domain 8: regression coverage for the phase switcher labels and Office Review routing.

## Decisions
- D-MAINT-CR043 accepted default: only user-facing phase numbers are renumbered sequentially. Backend `current_phase`, API paths, and legacy route names remain unchanged for compatibility.
- D-MAINT-CR043 accepted default: Add Evidence displays as visible Phase 5, Office Review as visible Phase 6, and Check Actions as visible Phase 7.
