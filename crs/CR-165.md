# CR-165 - Technical Superintendent Certs Catalog Edit Authority

**What & why** - Technical Superintendent users need the same normal Certs catalog maintenance path as Marine Superintendent: add rows, edit rows, and deprecate rows, while bulk soft-delete remains separately permissioned. This change adds Technical Superintendent to the catalog write gates when the profile carries catalog edit process permission.

**Tier + triggers** - Tier 2; changed role permission behavior for Certs catalog write actions.

**Domains touched** - Step 1 Certs catalog administration and office permissions.

**Decisions** - No new SSOT decision. Accepted default: Technical Superintendent receives normal catalog edit/deprecate authority through `CERT_P_008`; `Senior Technical Superintendent` is not automatically expanded by the seed and bulk catalog action `CERT_P_009` remains excluded.

**Doc cascade** - `Docs/OFFICE_CERTS_USER_GUIDE.md` now lists Technical Superintendent among catalog add/edit/deprecate users when the profile has catalog edit permission. Backend structure docs unchanged because no table, endpoint, or payload contract changed.

**Tests** - Extended backend permission coverage that Technical Superintendent with `CERT_F_001` and `CERT_P_008` passes the catalog writer gate, including the real login shape where `role` is `OFFICE_SUPT` and `role_name` is `Technical Superintendent`; added seed coverage that Technical Superintendent receives catalog edit without bulk action, guard coverage that Senior Technical Superintendent does not gain catalog edit through the seed, and frontend static coverage that the catalog writer gate checks profile role candidates before generic office role codes.

**Fidelity check** - No deltas. The backend permission gate, frontend button gate, seed bundle, and office guide now agree on Technical Superintendent catalog edit/deprecate authority, including office users whose generic workflow role is `OFFICE_SUPT`, with bulk action still withheld.

**Exemptions** - none.
