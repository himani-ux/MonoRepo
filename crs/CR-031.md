# CR-031 - Replace Incident Type Master List

## What & why

The Incident Type dropdown must use the new vessel-incident list provided by the user. The master data should expose these options for new Incident Phase 1 reporting, in the same order as provided, so users can classify collisions, allisions, bottom-touch events, equipment failures, security/cyber events, injuries, pollution, and Other more precisely.

## Tier + triggers

Tier 3 - structural Maintain Mode change. Triggers: changed incident type master data, changed Incident Phase 1 dropdown/validation behavior, and data migration touching existing master table data.

## Domains touched

Step 1 domains to verify: Incident Phase 1 report form, incident type master data, incident serializer/API contract compatibility, migrations/seed data, frontend regression tests, backend regression tests, implementation plan amendment, and canonical safety documentation.

## Decisions

- `D-MAINT-CR031` - replace the active Incident Type master list with the user-provided options, preserving the provided order for dropdown display.
- Accepted default: existing incident records remain readable; retired previous incident-type rows must not appear for new selection after the master update.
