**What & why**
Move the injury context fields away from the Type of Activity area and into the Injury Reporting section so users do not treat vessel/location context as part of activity selection. Latitude and longitude should be available for incident and injury reporting using the existing incident coordinate fields unless implementation discovery proves separate injury coordinates are required.

**Tier + triggers**
Tier 2 - changed screen state and reporting field organization. Current discovery shows no new DB column is expected because incident latitude/longitude already exist and the listed injury context fields already exist on the injury table.

**Domains touched**
Step 1 domains: incident Phase 1 reporting UI, injury reporting UI, injury API payload mapping, frontend regression tests, user/admin documentation.

**Decisions**
Accepted default: do not add separate injury latitude/longitude DB columns; reuse existing incident latitude/longitude for both incident and injury reporting. DB changes: none. The six injury-reporting context fields already exist on `vims_safety_external_party_injury` and remain in the same payload.
