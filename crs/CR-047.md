# CR-047 - Replace Incident Phase 7 Check Actions with Loss Evaluation

## What & why
The current visible Incident Phase 7 should no longer be Check Actions. It should become Loss Evaluation, with different field groups for Incident Report and Injury Report records. This gives the final post-review phase a structured risk, operational loss, cost, and repair/injury evaluation instead of action verification wording that no longer matches the requested workflow.

## Tier + triggers
Tier 3 - structural. Triggers: changes the documented visible incident workflow phase, contradicts current canonical Phase 7 Check Actions statements, adds persisted loss-evaluation data, changes frontend screen state, changes backend/API/PDF field contracts, and requires an append-only implementation-plan amendment.

## Domains touched
Step 1 Domains 2, 4, 5, 6, 7, and 8:
- Domain 2: visible Incident Phase 7 tab, route content, Incident-vs-Injury screen states, and user-facing wording.
- Domain 4: workflow semantics after Office Review, including how the final visible phase is completed.
- Domain 5: validation and optional/required behavior for Loss Evaluation fields.
- Domain 6: database/migration storage for loss-evaluation values and safe-working-practice dropdown readiness.
- Domain 7: frontend/backend/PDF/API field contract for incident and injury loss evaluation.
- Domain 8: regression tests for phase labels, Incident Report fields, Injury Report fields, persistence, and PDF output where applicable.

## Decisions
- D-MAINT-CR047 supersedes D-MAINT-CR043 only where the current visible Phase 7 is named or described as Check Actions. Visible Phase 7 is now Loss Evaluation.
- D-MAINT-CR047 accepted default: backend route names, legacy component names, and `current_phase` compatibility numbers remain unchanged unless code requires a minimal compatibility adapter.
- D-MAINT-CR047 accepted default: Loss Evaluation is stored as one editable record per incident and remains editable until incident closure/supersession.
- D-MAINT-CR047 accepted default: risk assessment choices are fixed dropdown values from the request: Consequence, Likelihood, and Risk level.
- D-MAINT-CR047 accepted default: `Code of Safe Working Practices to which the Incident relates` is nullable and master/dropdown-ready; options can be seeded in a later CR when provided.
