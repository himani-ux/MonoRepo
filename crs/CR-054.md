**What & why** - Phase 1 Incident Report should auto-fill the Vessel and Vessel code from the logged-in user's vessel context or the saved incident, and users should not be able to edit those two fields manually. This prevents inconsistent vessel identity and fixes cases where the vessel code is missing even though the vessel is known.

**Tier + triggers** - Tier 2. Triggers: changed Phase 1 screen state, changed field editability/validation expectations, and regression tests for vessel/vessel-code autofill behavior.

**Domains touched** - Domain 2 screen state and user input, Domain 4 workflow intake behavior, Domain 7 API/frontend contract for Phase 1 vessel identity, Domain 9 regression tests.

**Decisions** - D-MAINT-CR054 accepted default: Phase 1 displays Vessel and Vessel code as disabled identity fields after autofill/save; the frontend derives the values from the current user vessel context, single-vessel scope, or saved incident payload, does not allow manual vessel-code editing, and still sends the backend identifiers required for save/submit. Office users with multiple vessel options may select the vessel during new-report creation before that saved identity is locked.
