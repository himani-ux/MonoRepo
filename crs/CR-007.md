# CR-007 - Crew Activity Dropdown Master Extension

## What & why

Phase 1 crew injury details currently treat `Type of Activity` as free text. That makes the field inconsistent with the other crew injury reference fields and prevents controlled reporting. This change turns `Type of Activity` into a dropdown backed by the existing UUID master-table pattern, with `Others(Specify)` retained so the crew member can still enter an exact activity when the fixed list does not fit.

## Tier + triggers

Tier 2 - small feature / behavior change. Triggers: changed screen state, changed reference-data contract, and changed validation/documented field behavior. No new table is introduced; the existing UUID-backed injury dropdown master table is extended with a new `TYPE_OF_ACTIVITY` field key.

## Domains touched

Domains 2 and 3: Phase 1 injury sub-form behavior and backend reference-data surface.

## Decisions

No new SSOT decision ID assigned. The existing `vims_safety_injury_dropdown_option` master pattern remains the source of truth; `crew_activity_type` continues to store the selected label or typed `Others(Specify)` value.
