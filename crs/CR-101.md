**What & why**
Class Reconciliation snapshot upload currently stores the uploaded Class Status PDF as a pending snapshot and requires a separate Reparse click before parser output and reconciliation flags are produced. This change makes upload immediately run the parser and reconciliation path so the uploaded snapshot can produce a reconciliation run without an extra user action, while still keeping the manual Reparse action for recovery.

**Tier + triggers**
Tier 2 - small behavior change. Triggers: changed Certs upload workflow behavior, changed Class Reconciliation screen state after upload, and changed backend endpoint side effect for the existing class snapshot upload endpoint.

**Domains touched**
Step 1 domains: Certs class snapshot upload API, Certs parser/reconciliation workflow, Class Reconciliation frontend refresh/state, Certs tests, Certs backend/user documentation.

**Decisions**
Accepted default: perform parse + reconciliation synchronously during upload through the local `jobs/parser_worker.py` boundary for the current deployment, because no queued worker implementation exists locally. Manual Reparse remains available for failed/partial parser output and future parser fixes.

Accepted default: keep class-status snapshot PDFs text-extract only per D-CERT-048 and do not add OCR fallback in this CR. A scanned/image-only snapshot stores `parse_status=failed` with the parser reason, and the UI tells the user to upload the digital/text-selectable Class Status PDF from NK, KR, or BV.

**Doc cascade**
- `certs_docsuite/BACKEND_STRUCTURE.md` - update the class snapshot upload endpoint and parser flow to state that upload immediately runs parser/reconciliation in-process in this deployment, with Reparse retained for manual recovery and image-only PDFs recorded as text-extraction failures.
- `certs_docsuite/APP_FLOW.md` - update Class Reconciliation upload and recent snapshot state so upload creates a run-ready snapshot when parsing succeeds and shows a specific scanned/image-only PDF failure when there is no text layer.
- `certs_docsuite/USER_GUIDE.md` - update user workflow to say upload starts parsing/comparison automatically, requires a digital/text-selectable class-status PDF, and Reparse is only for retry/recovery.
- `certs_docsuite/PRD.md` - unchanged because D-CERT-048 already states class-status snapshot PDFs are text-extracted with no OCR fallback.
- `certs_docsuite/FIELD_MAP.md` - unchanged because no stored columns or field mappings change.

Added frontend source guard coverage for the vessel dropdown, upload copy, successful upload message, and image-only PDF failure message.

The mini-interrogation details are carried into docs: upload uses the vessel dropdown, upload immediately runs parse/reconciliation on success, Reparse remains a recovery action, and scanned/image-only class snapshot PDFs remain unsupported by the text-extract-only D-CERT-048 parser contract.
