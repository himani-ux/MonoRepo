# CR-041 - Add edit controls for saved incident phase 3-6 entries

## What & why
Saved entries in visible Incident phases 3, 4, 5, and 6 must be correctable from the screen where the user reviews them. Users should not need to create duplicate Corrective Action, Preventive Action, Lessons Learned, or Evidence Document/Witness Statement rows just to fix a saved value. Each saved item needs a clear Edit action that loads the existing values into the entry form and saves back to the same row while the incident remains editable.

## Tier + triggers
Tier 2 - small behavior/UI change. Triggers: new edit screen states for existing saved entries in current Incident Phase 3 Corrective Action, Phase 4 Preventive Action, Phase 5 Lessons Learned, and Phase 6 Add Evidence; changed endpoint contract for Phase 6 document metadata PATCH and Witness Statement PATCH because inspection showed those update paths were missing.

## Domains touched
Step 1 Domains 2, 5, and 8:
- Domain 2: Incident phase 3-6 saved-entry edit states and visible saved-card actions.
- Domain 5: validation/edit behavior for existing action, lesson, evidence document, and witness statement updates.
- Domain 8: frontend regression tests for editing saved phase 3-6 entries.

## Decisions
- D-MAINT-CR041 accepted default: saved entries in current phases 3-6 expose Edit controls while the incident remains editable.
- D-MAINT-CR041 accepted default: editing must update the existing saved row and must not create a duplicate entry.
- D-MAINT-CR041 accepted default: edit forms reuse the same validation, success acknowledgement, and scroll-to-saved-content behavior as create forms.
