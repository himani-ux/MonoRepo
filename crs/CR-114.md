**What & why**

Improve the Certs catalog add/edit form so users choose common catalog values from clear dropdowns instead of typing internal text values. Vessel-specific applicability must use vessel names instead of UUID entry, cadence months must accept clean numeric entry, and the hard-purge catalog action must be removed from the UI.

**Tier + triggers**

Tier 2 - small behavior/UI change. Triggers: changed catalog screen state, changed validation/input behavior, and removal of a user-facing action.

**Domains touched**

Step 1 domains: Certs catalog administration, vessel applicability, catalog lifecycle controls, and documentation/user guidance.

**Decisions**

Accepted defaults: reuse existing catalog rows/sections/vessel API data for dropdown choices; keep custom print section typing when no section labels exist; remove hard purge from the screen only, preserving existing backend compatibility unless a later CR explicitly removes the API.

**Doc cascade**

Updated `certs_docsuite/APP_FLOW.md` to describe dropdown catalog metadata controls, vessel-name selection for specific-vessel applicability, and the removal of the visible hard-purge action.
Updated `certs_docsuite/FIELD_MAP.md` to map the changed catalog editor controls and clarify that vessel names are selected while UUIDs remain the API storage value.
Updated `certs_docsuite/BACKEND_STRUCTURE.md` to clarify that the hard-purge endpoint remains a compatibility endpoint but no catalog screen control is rendered.
Updated `certs_docsuite/USER_GUIDE.md` to explain the DPA catalog edit workflow in user-facing terms.
Unchanged: `certs_docsuite/VALIDATION_RULES.md` because no backend validation rule changed; `certs_docsuite/TECH_STACK.md` because no dependency or stack changed; `certs_docsuite/SECURITY.md` because role permissions did not change.
