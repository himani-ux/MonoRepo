**What & why**
The Class Reconciliation upload form currently asks users to type a raw Vessel ID, which is not practical for office users because they choose vessels by name/code. This change replaces that free-text field with a vessel dropdown backed by the existing fleet dashboard data, while still submitting the selected vessel ID to the existing backend upload endpoint. The upload copy will also explain that "Upload snapshot" means uploading the vessel's official Class Status PDF from the class society.

**Tier + triggers**
Tier 2 - small behavior change. Trigger: changed screen state/UX for the existing Class Reconciliation upload form.

**Domains touched**
Certs frontend reconciliation screen, Certs user workflow documentation, Certs app flow documentation.

**Decisions**
No new SSOT decision. Existing backend contract remains unchanged: the upload payload still sends `vesselId`, `classSociety`, `printedOnDate`, and `file`.

**Doc cascade**
- `certs_docsuite/APP_FLOW.md` - update Class Reconciliation upload description to use a vessel dropdown and state what the PDF represents.
- `certs_docsuite/USER_GUIDE.md` - update the user workflow so DPA/office users select a vessel by name/code and upload the official class status PDF.
- `certs_docsuite/FIELD_MAP.md` - unchanged because no stored field, API payload, or DB mapping changes.
- `certs_docsuite/BACKEND_STRUCTURE.md` - unchanged because the backend tables and endpoint contract do not change.

**Tests**
Updated `psc-frontend/src/routes/certs/certs-route-validation.test.ts` so the Class Reconciliation form exposes a vessel dropdown and explanatory upload copy instead of the old Vessel ID free-text input.

**Fidelity check**
No deltas. The UI now selects vessels from onboarded fleet data by name/code/IMO while submitting the existing `vesselId`; the app-flow and user-guide docs both state that "Upload snapshot" means the latest official Class Status or Vessel Status PDF from the class society portal, not an individual certificate PDF.

**Exemptions**
None.
