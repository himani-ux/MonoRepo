**What & why** - Office users can see **Send for rework** on visible Phase 6 Office Review, but the backend send-back endpoint rejected records that had not already reached internal `current_phase = 7`. This caused the user-facing error `Office review actions require current_phase = 7.` when PIC/DPA tried to send an incident back with a rework comment. This change lets the send-back endpoint create the `SENT_BACK` rework state from an earlier internal phase while keeping the existing single-comment textbox and fixed action-rework target.

**Tier + triggers** - Tier 2. Trigger: endpoint validation rule changes for Incident Office Review send-back; visible workflow behavior is corrected for the existing Office Review screen state.

**Domains touched** - Step 1 domains: Incident Office Review, rework workflow/state transitions, backend validation, frontend/backend regression tests, and maintain-mode documentation.

**Decisions** - D-MAINT-CR079: Incident Office Review send-back is not blocked solely because the incident has not yet reached internal `current_phase = 7`. PIC/DPA with send-back permission can send the incident to the fixed action-rework phase with one comment; the incident becomes `SENT_BACK`, and the latest comment remains visible as the Rework summary until Rework Done returns it to Office Review/`UNDER_REVIEW`.

**Doc cascade** - `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` records D-MAINT-CR079 and updates Office Review send-back behavior. `safety_docsuite/IMPLEMENTATION_PLAN.md` adds a maintain-mode amendment. `safety_docsuite/APP_FLOW.md`, `safety_docsuite/PRD.md`, `safety_docsuite/USER_GUIDE.md`, `safety_docsuite/VALIDATION_RULES.md`, and `safety_docsuite/BACKEND_STRUCTURE.md` describe that send-back can create the sent-back rework state without requiring internal phase 7 first. `Docs/progress.txt` records the change. Other docs unchanged because they do not describe Incident Office Review rework validation.

**Tests** - Added backend regression coverage in `psc-backend/tests/safety/test_phase7_sendback.py` for sending a phase-3 incident to rework without the old `current_phase = 7` validation error. Existing frontend send-back test already confirms the current UI sends only the comment plus fixed target phase.

**Fidelity check** - no deltas. The user reported the exact backend validation error while clicking **Send for rework**; the backend no longer requires current phase 7 for send-back, while keeping role permission, reason validation, and fixed no-picker target behavior.

**Exemptions** - none.
