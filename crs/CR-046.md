# CR-046 - Allow up to three PDFs on Inspection follow-up registration

## What & why
Inspection follow-up registration should allow the user to attach up to three PDF files instead of being limited to a single attachment. This lets users provide multiple supporting PDFs during follow-up registration without creating separate follow-up entries.

## Tier + triggers
Tier 2 - small feature / behavior change. Triggers: changed screen state, changed upload validation rule, and changed frontend/backend request contract for Inspection follow-up registration attachments.

## Domains touched
Step 1 Domains 2, 5, 7, and 8:
- Domain 2: Follow-up registration UI must let users select and review up to three PDF attachments.
- Domain 5: Validation must allow 1-3 PDF attachments and reject more than three or non-PDF files.
- Domain 7: Follow-up registration request handling must accept multiple attachment files under the chosen contract.
- Domain 8: Regression tests must cover multiple accepted PDFs and the three-file limit.

## Decisions
- D-MAINT-CR046 accepted default: maximum follow-up registration attachments is 3 files.
- D-MAINT-CR046 accepted default: allowed file type remains PDF-only.

## Doc cascade
- Docs/MASTER_INSPECTION_WORK_INSTRUCTION.md - follow-up registration now states up to three optional PDF report attachments, PDF-only, 5 MB each, with description required when attached.
- Docs/APP_FLOW.md - Register Follow-up upload control now shows "PDFs, max 3".
- Docs/PRD.md - FEAT-DEF-002 acceptance criteria now includes optional upload of up to three follow-up report PDFs.
- Docs/modules/backend/inspection.md - backend workflow now documents up to three optional follow-up report PDFs.
- Docs/modules/frontend/inspection-workflow.md - frontend route workflow now documents optional upload of up to three PDF reports.
- Docs/USER_GUIDE.md - PSC follow-up steps now mention optional upload of up to three PDF follow-up reports.
- Expected docs not updated: SHIP_INSPECTION_USER_GUIDE.md and OFFICE_INSPECTION_USER_GUIDE.md unchanged because they only list the Register Follow-up action and do not describe attachment behavior.

## Tests
- Added frontend validation tests for allowing three PDFs and rejecting more than three, non-PDF, and over-5MB files.
- Added frontend route test proving three selected PDFs are submitted as repeated `report_files` form-data entries.
- Added backend helper tests for collecting repeated `report_files` plus legacy `report_file`, and validating max three, PDF-only, and 5 MB rules.
- Added backend endpoint regression tests for accepting three PDFs and rejecting four PDFs; direct Django execution is blocked before these tests run by the existing Safety SQLite migration failure `no such column: legacy_int_id` in `safety.0002_seed_master_tables`.

## Fidelity check
No deltas. The implemented behavior matches the CR decisions: maximum 3 attachments, PDF-only, 5 MB each, and the old single-file `report_file` field remains accepted for compatibility.
