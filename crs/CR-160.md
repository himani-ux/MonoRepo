**What & why** - The Audit Qualified Auditors screen should not depend on a hardcoded frontend list for `Qualifying Body`. This change adds a database-backed master table named `aud_master_qual_body` so approved qualifying bodies can be managed centrally and used by the Qualified Auditors dropdown.

**Tier + triggers** - Tier 3. Triggers: new database table, new migration, new read API endpoint contract, and frontend dropdown source changes. No auth/session model change, external integration, or new dependency is planned.

**Domains touched** - Step 1 domains: Audit master-data maintenance; qualified-auditor qualification evidence; Audit API master-data contracts; Audit frontend master-data screen; Audit user/admin documentation.

**Decisions** - D-MAINT-CR160: create `aud_master_qual_body` with UUID primary key, `body_name`, `is_active`, and `is_deleted`. The table is the dropdown source for Qualified Auditors. Existing `master_audit_qualified_auditor.qualifying_body` remains a text snapshot of the selected body name, so existing qualified-auditor rows do not require destructive data conversion.

**Doc cascade** - `Docs/IMPLEMENTATION_PLAN.md` amended for the new Audit qualifying-body master table. `audit_docsuite/BACKEND_STRUCTURE.md` documents the table and endpoint. `audit_docsuite/GAPS_2.md`, `audit_docsuite/resolution response.md`, and `audit_docsuite/USER_GUIDE.md` updated to state that Qualifying Body is DB-backed. `audit_docsuite/APP_FLOW.md` unchanged because user flow remains the same dropdown workflow. `Docs/progress.txt` updated.

**Tests** - Added backend API permission, route, serializer, and SQL Server-safe migration seed coverage plus frontend coverage that the Qualified Auditors screen renders Qualifying Body options from the API-backed hook.

**Fidelity check** - no deltas. The migration creates `aud_master_qual_body` with UUID primary key, `body_name`, `is_active`, and `is_deleted`; the API is gated by `AUDIT_P_009`; the frontend dropdown uses the API-backed master rows; existing qualified-auditor records continue to store the selected body name in `master_audit_qualified_auditor.qualifying_body`.

**Exemptions** - none.
