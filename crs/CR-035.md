# CR-035 - Make Incident Weather Migration Idempotent

## What & why

Running migrations can fail at `safety.0043_incident_weather_condition_fields` when the SQL Server database already contains `vims_safety_incident_weather_option`. The migration should tolerate that pre-existing table, keep Django migration state aligned, and continue applying the remaining weather-condition columns/indexes without requiring a manual table drop.

## Tier + triggers

Tier 3 - structural Maintain Mode change. Triggers: migration behavior changes for an existing database object and existing-data compatibility for a table that may already exist outside Django migration state. No new business fields are introduced.

## Domains touched

Step 1 domains to verify: Safety migration chain, incident weather option table creation/state alignment, incident weather fields, migration regression checks, and canonical backend/implementation documentation.

## Decisions

- `D-MAINT-CR035` - pending implementation: `safety.0043_incident_weather_condition_fields` must be safe when `vims_safety_incident_weather_option` already exists and must still register the Django model state for later migrations.
