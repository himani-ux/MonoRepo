**What & why**

Users should not be stopped by a duplicate-PDF error when uploading a certificate file. This change removes the same-file upload block: if the uploaded PDF already exists for that certificate, the system reuses the stored PDF blob, runs OCR again from the uploaded file, updates the certificate fields, and returns the normal upload success response.

**Tier + triggers**

Tier 2 - changed validation rule for certificate PDF upload.

**Domains touched**

Step 1 Certs certificate upload, OCR/reparse workflow, and PDF blob retention/idempotency.

**Decisions**

No new SSOT decision. Accepted default: exact same PDF uploads are allowed; duplicate storage is avoided by reusing the existing blob row while still processing the upload as a normal user action.

**Doc cascade**

- `certs_docsuite/APP_FLOW.md` - clarify that uploading the same PDF again is accepted and reprocesses against the existing stored PDF record.
- `certs_docsuite/BACKEND_STRUCTURE.md` - clarify upload endpoint behavior for a matching active PDF blob.
- Expected docs not updated: Certs user guides unchanged because they already direct users to upload/read PDF again and did not document the removed duplicate block.
