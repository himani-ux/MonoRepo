**What & why**

Remove the witness free-text statement from the Incident PDF. The system should not print the `What the witness said` content even when legacy database rows contain a value, because witness evidence is represented by the witness identity/rank/remark and attachment link instead.

**Tier + triggers**

Tier 2 - small behavior change. Trigger: changed generated PDF output contract.

**Domains touched**

Step 1 safety incident PDF/reporting output and witness evidence presentation.

**Decisions**

D-MAINT-CR072: Incident PDFs suppress witness statement text unconditionally. Legacy or accidental values in the database are not rendered.

**Doc cascade**

- `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` - update the PDF witness output rule.
- `safety_docsuite/APP_FLOW.md` - update the user-facing PDF flow notes for witness output.
- `safety_docsuite/USER_GUIDE.md` - update the PDF witness description.
- `safety_docsuite/PRD.md` - update the printable incident report behavior.
- `safety_docsuite/BACKEND_STRUCTURE.md` - update backend PDF renderer behavior.
- `safety_docsuite/VALIDATION_RULES.md` - update the current PDF output summary so it also states witness statement text is suppressed.

**Tests**

Focused PDF regression test to ensure witness statement text is not present even when source data contains it.

**Fidelity check**

No deltas. The renderer, regression test, SSOT, and docs all state the same rule: Witness Statement PDF blocks may show the witness-heading, downloadable attachment link, and Remark, but they do not print `What the witness said` or legacy free-text witness statement values.

**Exemptions**

None.
