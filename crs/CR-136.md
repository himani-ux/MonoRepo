**What & why** - The simplified Safety Dashboard became too plain after CR-135. This change keeps the same clean summary-first workflow, but adds lightweight visual charts to the default dashboard so users can quickly understand the spread of open work and the safety score breakdown without opening the detailed analytics area.

**Tier + triggers** - Tier 2. Triggers: changed Safety Dashboard screen presentation and visible layout. No endpoint, payload, permission, dependency, or database change.

**Domains touched** - Step 1 domains: Safety Dashboard presentation, dashboard summary cards, optional analytics visibility, frontend route tests, and maintain-mode documentation.

**Decisions** - D-MAINT-CR136: `/safety/dashboard/` keeps the PSC-style simple header, compact filters, KPI cards, and **Show details** area from CR-135, but the default summary area also displays two compact visual panels: open work by type and score breakdown. These charts use the existing composite dashboard response and do not change calculations, endpoints, export permissions, or detailed analytics.

**Doc cascade** - `safety_docsuite/PRD.md` describes the default charted summary. `safety_docsuite/APP_FLOW.md` records the current dashboard route presentation. `safety_docsuite/USER_GUIDE.md` explains that open-work and score-breakdown charts show first. `safety_docsuite/VALIDATION_RULES.md` records that the charts use the existing composite response and keep **SOI Compliance %** wording unchanged. `safety_docsuite/IMPLEMENTATION_PLAN.md` adds Amendment 39. `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` adds D-MAINT-CR136. `safety_docsuite/BACKEND_STRUCTURE.md` unchanged because no backend route, table, payload, or permission contract changes. `Docs/progress.txt` records the change.

**Tests** - Updated the existing dashboard route test to assert the new chart labels. `npm run test -- src/routes/safety/index.test.tsx -t dashboard` passed. `npm run type-check` passed. `npm run build` passed with existing Vite idb/chunk-size warnings.

**Fidelity check** - no deltas. The code, PRD, app flow, user guide, validation rules, implementation amendment, and SSOT decision all describe the same behavior: a simple dashboard with summary KPI cards plus open-work and score-breakdown charts, with detailed analytics still hidden behind **Show details** and no backend/API changes.

**Exemptions** - none.
