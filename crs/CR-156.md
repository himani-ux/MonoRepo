**What & why** - HOD/CE/CO Near Miss review comments are currently stored in field history but are not shown in the main Near Miss detail summary. This change exposes the latest HOD/CE/CO review comment through the Near Miss API and renders it on the UI next to the existing Master vessel-review comment so users can see the full onboard review chain without opening History.

**Tier + triggers** - Tier 2. Triggers: changed API response contract for Near Miss detail/list serialization and changed Near Miss detail screen state.

**Domains touched** - Step 1 domains: Near Miss vessel review workflow; HOD/CE/CO review visibility; Near Miss detail API contract; Near Miss UI summary; Safety field-history display.

**Decisions** - D-MAINT-CR156: Near Miss exposes `hod_review_summary` from the latest `near_miss_hod_review_signature` field-history row. The existing `vessel_review_summary` remains the Master vessel-review summary. Both summaries use the same comment/decision/reviewer/typed-name shape and suppress fallback boilerplate comments.

**Doc cascade** - `safety_docsuite/APP_FLOW.md` states that HOD/CE/CO and Master review comments render separately on the Near Miss detail summary. `safety_docsuite/BACKEND_STRUCTURE.md` documents the additive `hod_review_summary` API field. `safety_docsuite/USER_GUIDE.md` explains that HOD/CE/CO review comments remain visible beside the Master vessel-review comment. `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` unchanged because this is display/API clarification of existing review storage, not a new Safety decision. `safety_docsuite/VALIDATION_RULES.md` unchanged because no validation rule changes. `safety_docsuite/PRD.md` unchanged because FEAT-SAF-NM-002 already requires authorized review visibility and this narrows UI rendering only.

**Tests** - Added backend coverage to confirm CE/HOD review comments remain available after Master submission, and frontend coverage to confirm the HOD/CE/CO review comment renders before the Master vessel-review and office comments in the Near Miss summary.

**Fidelity check** - no deltas.

**Exemptions** - none.
