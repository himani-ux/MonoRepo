# CR-036 - Phase 4 Witness Statement Simplification

## What & why

Phase 4 evidence should make witness capture clearer. The collapsed Optional section should be renamed to Witness Statement and take the user directly to the witness-note page. Witness name should be selected from the crew list for the incident vessel, with an Other option that lets the user type an external witness name. Witness notes should support attaching a signature image, and Closing note should be renamed Remark.

## Tier + triggers

Tier 3 - structural Maintain Mode change. Triggers: changed Phase 4 screen state, changed witness-note payload behavior, possible storage/attachment association change for signature upload, and supersession of canonical docs that currently describe the Phase 4 supporting tool as optional Witness Notes with Witness name / What the witness said / Closing note only.

## Domains touched

Step 1 domains to verify: Incident Phase 4 Evidence UI/screen state, witness-note route behavior, vessel crew lookup/source, witness-note payload compatibility, signature image attachment handling, Incident PDF witness-note output if applicable, frontend regression tests, backend validation/serialization if applicable, and canonical safety documentation.

## Decisions

- `D-MAINT-CR036` - Phase 4 supporting witness capture is presented as Witness Statement, links directly to `/phase-4/interviews/`, uses incident vessel crew-or-Other witness selection, supports optional signature image upload through the existing `witness_signature` field, and uses Remark wording in UI/PDF.
- Default accepted for implementation: no new DB table or column was needed because the legacy witness-interview payload already has `witness_signature`.
