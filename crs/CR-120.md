**What & why** - The Conditions of class review bucket must now be strict for every supported class society, not only BV. Users should see only content from actual "Condition of Class" / "Conditions of Class" sections; nearby action notes, installation conditions, statutory survey conditions, memoranda, or similar sections must not appear as Conditions of class.

**Tier + triggers** - Tier 3 structural/docs correction. Trigger: this supersedes current parser/docs behavior that allowed non-COC sections such as KR Actionable Note and NK Condition of Installation / Condition of Statutory Survey to populate the Conditions of class review bucket.

**Domains touched** - Step 1 domains: class snapshot parser, class snapshot reconciliation review payload, Certs review UI data contract, parser regression tests, Certs SSOT/docsuite.

**Decisions** - D-CERT-207 supersedes D-CERT-066 and D-CERT-206 where any supported class parser or doc allowed non-COC sections into `conditions_of_class[]`. Accepted default: for NK, KR, and BV reports, `conditions_of_class[]` and Conditions of class review flags are populated only from exact Condition of Class / Conditions of Class source sections.

**Doc cascade** - Update `certs_ssot/VIMS-CERTIFICATES-MODULE-SSOT.md` with D-CERT-207. Update `certs_docsuite/IMPLEMENTATION_PLAN.md` with Amendment 8. Update `certs_docsuite/APP_FLOW.md`, `certs_docsuite/BACKEND_STRUCTURE.md`, `certs_docsuite/FIELD_MAP.md`, `certs_docsuite/PRD.md`, and `certs_docsuite/USER_GUIDE.md` to describe strict all-class Conditions of class behavior. Update `Docs/LESSONS.md` to strengthen the class-report section-classification rule. Expected unchanged: `TECH_STACK.md` unchanged because no runtime/dependency choice changes; `VALIDATION_RULES.md` unchanged because no user-entered validation rule changes.

**Tests** - Add/adjust parser and reconciliation regressions proving KR Actionable Note, NK Condition of Installation, NK Condition of Statutory Survey, and BV memoranda do not populate Conditions of class, while exact Condition of Class rows still do.

**Fidelity check** - no deltas. Code, tests, SSOT, implementation-plan amendment, and docsuite wording all state the same behavior: only exact Condition of Class / Conditions of Class sections populate `conditions_of_class[]`; action notes, installation/statutory condition sections, and memoranda are excluded.

**Exemptions** - none.
