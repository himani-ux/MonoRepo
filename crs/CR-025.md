**What & why**

Estimated cost entry in the injury form is being changed from always-visible fields to an explicit user choice. The form now asks whether estimated cost details should be added; choosing Yes shows the cost inputs, while choosing No hides them and keeps incident/injury reporting able to continue without cost data.

**Tier + triggers**

Tier 2 - small behavior change. Trigger: new screen state and user-facing validation behavior for the Phase 1 injury estimated cost section.

**Domains touched**

Step 1 domains touched: Safety incident reporting UI, injury reporting data capture, validation, and user documentation.

Mini-interrogation:
- Should this add a database column? No. Existing estimated cost fields are already nullable and the requested behavior is a screen-state choice.
- Should No block submission? No. No keeps the cost fields hidden and allows continuation without cost details.
- Should existing saved cost data still be visible? Yes. If an existing injury record has any estimated cost value, the form opens with the cost fields visible so the user can review or edit them.

**Decisions**

No new SSOT decision ID required; this refines the existing injury estimated cost capture behavior without changing stored data shape.
