**What & why**

All active Certs catalog rows were changed to `all_ranks_with_approval` so Chief Officer, Chief Engineer, and Second Engineer can upload certificate PDFs for their vessel. Previously every local catalog row was `master_only`, so the backend sub-officer upload path existed but had no usable certificate rows.

**Tier + triggers**

Tier 3 - structural. Triggers: changed role-permission behavior through catalog configuration, live data update affecting all Certs catalog rows, and contradiction of canonical D-CERT-079/D-CERT-165 statements that Class/Statutory/class-tracked rows remain `master_only`.

**Domains touched**

Step 1 domains: RBAC and approval workflow, catalog metadata, tracked-item upload workflow, user guidance.

**Decisions**

Added D-CERT-199, superseding D-CERT-079 and D-CERT-165 only where they assign any certificate category to `master_only`.
