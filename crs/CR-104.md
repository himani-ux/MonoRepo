# CR-104

## What & why
Seed the Certs class-code mapping table with the approved KR baseline extracted from the Ayuthya class-status PDF so class snapshot reconciliation can map parsed KR codes/names to existing catalog rows instead of putting every parsed row into "missing in catalog".

## Tier + triggers
Tier 2 - small behavior/data change. Trigger: reconciliation behavior changes because approved master mapping data is added for the existing `vims_certs_class_code_mapping` table. No schema migration, endpoint change, UI change, role change, or dependency change is required.

## Domains touched
Step 1 domains touched: Certs catalog/master data, class snapshot reconciliation, parser-to-catalog mapping, backend seed command, backend regression tests, and Certs documentation.

Mini-interrogation:
- Mapping source: approved by the user on 2026-07-22 from the uploaded Ayuthya KR class-status PDF; if a mapping is later found wrong, it will be corrected through the existing mapping edit path.
- Seed scope: KR baseline rows emitted by the current parser for Ayuthya; no NK/BV guesses in this change.
- Existing mappings: never overwrite active mappings; skip them so production edits remain authoritative.
- Catalog handling: use existing catalog rows only; do not invent catalog rows in this change.
- Validity handling: no automatic tracked-item validity update in this change; reconciliation mapping only.
- UI: no UI changes.
