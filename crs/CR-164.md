# CR-164 - Marine Superintendent Certs Catalog Edit Authority

**What & why** - Marine Superintendent users already have Certs catalog visibility, but the catalog write gates only allowed DPA, SEQ Manager, and admin roles. This change lets Marine Superintendent users add, edit, and deprecate certificate catalog rows when their profile also carries the catalog edit process permission.

**Tier + triggers** - Tier 2; changed role permission behavior for Certs catalog write actions.

**Domains touched** - Step 1 Certs catalog administration and office permissions.

**Decisions** - No new SSOT decision. Accepted default: Marine Superintendent receives normal catalog edit/deprecate authority through `CERT_P_008`; bulk catalog action `CERT_P_009` remains excluded unless separately approved.

**Doc cascade** - `Docs/OFFICE_CERTS_USER_GUIDE.md` now lists Marine Superintendent among catalog add/edit/deprecate users when the profile has catalog edit permission. Backend structure docs unchanged because no table, endpoint, or payload contract changed.

**Tests** - Added backend permission coverage that Marine Superintendent with `CERT_F_001` and `CERT_P_008` passes the catalog writer gate, and seed coverage that the Marine Superintendent bundle includes catalog edit but not bulk action.

**Fidelity check** - No deltas. The backend permission gate, frontend button gate, seed bundle, and office guide now agree on Marine Superintendent catalog edit/deprecate authority, with bulk action still withheld.

**Exemptions** - none.
