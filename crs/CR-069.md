**What & why** - Incident PDFs should render Corrective Actions and Preventive Actions as clean full-width action boxes. The current label/value table repeats a left-side `Description` label for every action, which creates an unnecessary vertical split and makes the action section harder to read.

**Tier + triggers** - Tier 2; the generated Incident PDF contract changes.

**Domains touched** - Safety incident PDF generation, Corrective Action PDF output, Preventive Action PDF output, and safety documentation.

**Decisions** - Added `D-MAINT-CR069` as an append-only SSOT decision. It supersedes `D-MAINT-CR067` only for current Incident PDF action-box layout and due-date capitalization.

**Doc cascade** - `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` adds `D-MAINT-CR069` and updates current action PDF wording. `safety_docsuite/APP_FLOW.md`, `safety_docsuite/USER_GUIDE.md`, `safety_docsuite/PRD.md`, `safety_docsuite/BACKEND_STRUCTURE.md`, and `safety_docsuite/VALIDATION_RULES.md` describe full-width Corrective/Preventive action boxes with Description text first and `Due Date: YYYY-MM-DD` second when a due date exists. `safety_docsuite/IMPLEMENTATION_PLAN.md` unchanged because no Tier 3 amendment is required. Other canonical docs unchanged because they do not describe this row-level PDF layout.

**Tests** - Updated `tests.safety.test_pdf_10_sections` to assert action PDF blocks use unlabeled full-width rows, keep the category headings, and print `Due Date: YYYY-MM-DD` without a repeated `Description` label column.

**Fidelity check** - no deltas. Mini-interrogation findings match implementation: existing action descriptions remain the first line, linked due dates remain sourced from saved `vims_safety_corrective_action.due_date` rows, and the PDF template renders these entries as full-width bordered boxes instead of label/value rows.

**Exemptions** - None.
