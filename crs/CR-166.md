**What & why**
Complete the registered audit UI so users can find audits after registration and open the existing audit detail screen from the Audit Dashboard. The current flow creates registered audits and navigates immediately to detail, but there is no durable dashboard list for later access.

**Tier + triggers**
Tier 2 - small feature / behavior change. Triggers: new screen state on the Audit Dashboard and a read contract on the existing audit registration endpoint.

**Domains touched**
Audit workflow/navigation: `D-AUDRS-037`, `D-AUDRS-039`, `D-AUDRS-084`.
Audit access scoping: `D-AUDRS-086`.

**Decisions**
Accepted default: surface registered audits on the existing Audit Dashboard rather than adding a new top-level route.
Accepted default: use `GET /api/audit/audits/` for registered audit summaries and keep `POST /api/audit/audits/` for registration.
Accepted default: the Open action routes to the existing `/audit/audits/:id` detail screen.
Accepted default: no database schema change.
