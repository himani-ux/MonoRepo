**What & why** - The Certs Print Builder and Share Bundle screens currently ask users to type vessel IDs and certificate IDs manually. This change replaces those manual ID inputs with vessel and certificate pickers so users can choose familiar vessel and certificate labels, while preserving the same backend payloads. The recipient email field remains the same visible field but uses browser email validation to reduce typing mistakes.

**Tier + triggers** - Tier 2. Triggers: changed screen controls/state for Print Builder and Share Bundle, and changed validation rule for recipient email entry.

**Domains touched** - Certs print/share workflow, Certs vessel selection data flow, Certs certificate selection data flow, frontend form validation, user-facing Certs documentation.

**Decisions** - No new SSOT decision. Accepted defaults: use the existing Certs fleet vessel list for vessel choices, keep the existing print/share API payload shape, and load certificate choices from the selected vessel context so users do not need to know internal IDs.

**Doc cascade** - `certs_docsuite/APP_FLOW.md` updated to describe vessel and certificate dropdowns in print/share flows. `certs_docsuite/USER_GUIDE.md` updated with the user-facing print/share workflow. `certs_docsuite/BACKEND_STRUCTURE.md` unchanged because no API endpoint or payload contract is changed.

**Tests** - Added frontend route validation covering the print/share vessel picker labels, certificate picker labels, and email input validation.

**Fidelity check** - no deltas. The implemented controls match the accepted defaults: vessel choices come from the existing fleet dashboard list, certificate choices come from the existing tracked-item list filtered by selected vessels, the print/share API payload shape is unchanged, and the docs describe the post-change user flow.

**Exemptions** - none
