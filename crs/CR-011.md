**What & why**
Incident editing and downstream incident controls need to preserve entered injury data, enforce the intended Phase 2 and Phase 5 validations, and print the required signature block consistently. This change keeps Phase 1 edits persistent after an incident has moved forward, prevents empty injury payloads from deleting existing injury records, restores IMO classifier validation, restores the Phase 5 major-finding evidence gate, and keeps unsigned required PDF signature rows visible as pending.

**Tier + triggers**
Tier 2. Triggered by changed API update semantics, changed validation behavior, changed incident phase screen behavior, and regression-test updates.

**Domains touched**
1. Incident Phase 1 intake and injury capture
2. Incident Phase 2 office communication and IMO validation
3. Incident Phase 5 evidence/root-cause gate
4. Incident PDF export and signature rendering
5. Incident frontend phase editing

**Decisions**
1. Empty or null `external_party_injury` on an update means "leave existing injury unchanged"; a populated injury payload still creates or updates the injury record.
2. Explicit IMO classifier selections are preserved and validated; only missing classifier values default to `NOT_APPLICABLE`.
3. Required signature labels are rendered in the PDF even when unsigned, with a pending status instead of hiding the row.
4. Phase 1 edit saves persist to the backend for existing incidents before local draft state is updated.
