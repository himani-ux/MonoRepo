**What & why** - Normal Certs Print Builder PDFs should be cleaner and avoid exposing internal artifact labels in the visible report body. This change removes the printed report title/header, scope wording, print ID, hash, validity legend/column, recipient name, and generation footer from the normal print PDF. It keeps the stored print ID/hash in DB/API/audit and changes the visible generator label from `User` to `Printed by`. If a watermark is selected, only the watermark label prints at the bottom-right of each page.

**Tier + triggers** - Tier 3. Trigger: this supersedes canonical print-output statements in `certs_docsuite/IMPLEMENTATION_PLAN.md`, `certs_docsuite/PRD.md`, `certs_docsuite/DESIGN_SYSTEM.md`, `certs_docsuite/SECURITY.md`, and `certs_docsuite/FIELD_MAP.md` that previously required printed footer identifiers and validity glossary output.

**Domains touched** - Certs print/export workflow, print PDF rendering, print artifact documentation, security/identifiability documentation, backend regression tests.

**Decisions** - D-CERT-202 added in `certs_docsuite/IMPLEMENTATION_PLAN.md` Amendment 5. Stored print artifact identifiers remain immutable in `vims_certs_print_artifact`, API responses, audit metadata, filenames, and history. Normal user-facing print PDFs no longer print header/scope/print ID/hash/validity/recipient/generation-footer metadata. Watermark choice prints as a bottom-right label on each normal print PDF page without the recipient name.
