# CR-018 - Remove Phase 1 First Checks

## What & why

The Phase 1 "First Checks" / first-hour checklist should be removed completely from the current user-facing incident flow. Users should not see the checklist, toggle it, or send `first_hour_checklist_done` from the frontend; the existing backend column remains only for historical/backward-compatible records.

## Tier + triggers

Tier 3 - structural Maintain Mode change. Triggers: changed Phase 1 screen state and frontend payload behavior, changed validation/documentation contract, and contradiction of canonical PRD/APP_FLOW/VALIDATION/SSOT statements that still describe the first-hour scene-protection checklist as a required Phase 1 control.

## Domains touched

Step 1 domains to verify: Incident Phase 1 UI/screen state, Phase 1 create/edit payloads, frontend schemas/tests, backend compatibility, validation/docs wording, and canonical safety documentation.

## Decisions

New SSOT decision `D-MAINT-CR018`: the current user-facing incident flow does not expose or require the first-hour/First Checks checklist. The existing `first_hour_checklist_done` backend column remains for historical compatibility only and is not sent by the current frontend. This supersedes `D-GAP-R07` for the current user-facing Incident Phase 1 workflow.
