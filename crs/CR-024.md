**What & why**
Move Shore Assistance Required, Location of Vessel, Location on Board, Last Port, Departure Date, and Vessel Condition into the main Phase 1 Incident Report section so the fields are visible for normal incident reporting and are not hidden behind the injury toggle. The values become incident-level context shared by Incident and Injury reporting.

**Tier + triggers**
Tier 3 - adds nullable columns to the existing incident table through a migration and changes the Phase 1 API/UI contract. Triggering discovery: the fields currently exist only on `vims_safety_external_party_injury`, so they cannot be saved for an incident unless an injury row exists.

**Domains touched**
Step 1 domains: incident Phase 1 reporting UI, incident Phase 1 API serializer/create/update contract, incident model/migration, injury reporting UI field placement, incident PDF/reporting output if rendered from incident context, frontend/backend regression tests, canonical docs.

**Decisions**
Accepted default: add nullable incident-level columns for the six shared reporting fields, keep the existing injury-table columns for backward compatibility, and render the fields once in the main Phase 1 Incident Report block. When printing injury details, incident-level values are the source of truth with fallback to legacy injury-row values for older records.
