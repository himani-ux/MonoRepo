**What & why** - The Audit Qualified Auditors screen should not require users to manually type an Employee/User ID. This change adds a process-gated Audit lookup for active office users from the existing `users` master table and changes the Qualified Auditors form to select an office user from a dropdown showing display name and mapped office role.

**Tier + triggers** - Tier 2. Triggers: new read-only API endpoint contract and changed frontend screen state for the Qualified Auditors maintenance form.

**Domains touched** - Step 1 domains: Audit master-data maintenance; qualified-auditor identity sourcing; office-user master lookup; Audit process permission gating.

**Decisions** - D-MAINT-CR157: Qualified Auditor maintenance uses active, non-deleted office users from `dbo.users` that also have an active mapped role in `mapping_role_user` -> `master_role`. The saved value remains `users.employee_id` in `master_audit_qualified_auditor.user_id`; dropdown labels include display name and mapped `master_role.role_name` only. The new lookup endpoint is gated by existing `AUDIT_P_009`.

**Doc cascade** - `audit_docsuite/BACKEND_STRUCTURE.md` documents the office-user lookup endpoint and mapped role source. `audit_docsuite/GAPS_2.md` records that the Qualified Auditors UI now selects existing office users instead of manual identity entry. `audit_docsuite/resolution response.md` updated to reflect the active local behavior. `Docs/IMPLEMENTATION_PLAN.md` unchanged because this is an additive Maintain-mode screen/lookup refinement within the existing Audit master-data resolution.

**Tests** - Added backend route/response coverage for the office-user lookup and frontend coverage that the Qualified Auditors form renders the office-user role in the dropdown and saves the selected `employee_id`.

**Fidelity check** - no deltas.

**Exemptions** - none.
