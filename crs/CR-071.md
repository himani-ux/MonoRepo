**What & why** - Incident PDFs should not print vessel-location detail as a separate `Specific vessel location` row. When a port or anchorage detail is recorded, the PDF should show it in the same Vessel location value, such as `In Port - Singapore`; when the selected location has no detail, the PDF should print only the selected location and not a `Not recorded` detail row.

**Tier + triggers** - Tier 2; the generated Incident PDF contract changes.

**Domains touched** - Safety incident PDF generation, Phase 1 reporting-context PDF output, injury detail PDF output, and safety documentation.

**Decisions** - Added `D-MAINT-CR071` as an append-only SSOT decision. It supersedes `D-MAINT-CR065` only where current Incident PDFs printed Location of Vessel and Specific vessel location separately.

**Doc cascade** - `safety_ssot/VIMS-SAFETY-MODULE-SSOT.md` adds `D-MAINT-CR071` and updates current vessel-location PDF wording. `safety_docsuite/APP_FLOW.md`, `safety_docsuite/PRD.md`, `safety_docsuite/USER_GUIDE.md`, `safety_docsuite/VALIDATION_RULES.md`, and `safety_docsuite/BACKEND_STRUCTURE.md` now describe one Vessel location row combining port/anchorage detail when present. `safety_docsuite/IMPLEMENTATION_PLAN.md` unchanged because no Tier 3 amendment is required. Other canonical docs unchanged because they do not describe this row-level PDF layout.

**Tests** - Updated `tests.safety.test_pdf_10_sections` to assert the generated PDF prints `In Port - Singapore` in one Vessel location row and does not print a separate Specific vessel location row.

**Fidelity check** - no deltas. Mini-interrogation findings match implementation: `vessel_location_detail` remains stored for In Port / At Anchorage, current PDFs combine it into the Vessel location value, and at-sea selections do not emit a separate `Not recorded` detail row.
