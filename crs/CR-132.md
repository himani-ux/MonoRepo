**What & why**

Marine Superintendent users can open the SOI module, but the SOI findings register was blocked by a frontend process gate even though the backend list endpoint only requires SOI form access for read-only viewing. This change aligns the UI route with the backend contract so office users with SOI visibility can view findings, while create/upload/closure actions remain process-gated.

**Tier + triggers**

Tier 2 - changed screen access / role permission behavior for the SOI findings register.

**Domains touched**

Step 1 safety access control and SOI workflow.

**Decisions**

No new SSOT decision. The implemented default is: SOI findings register is readable with `SAF_F_004`; creating findings remains protected by SOI action permission and Safety Officer role gates.

**Doc cascade**

- `safety_docsuite/APP_FLOW.md` - clarify SOI finding register read access versus create action access.
- `safety_docsuite/BACKEND_STRUCTURE.md` - clarify backend endpoint auth for GET versus POST on SOI findings.
- Expected docs not updated: SSOT unchanged because this restores the current backend read contract instead of adding a new business rule.
