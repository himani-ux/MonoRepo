**What & why**
Replace the free-text DefCode entry in the Audit finding modal with the existing master-data DefCode picker. This prevents invalid manual DefCode typing and lets users search/select active deficiency codes by code and description while creating audit NC/observation findings.

**Tier + triggers**
Tier 2 - small feature / behavior change. Triggers: changed screen control behavior on the Audit finding modal and changed validation path from free text to master-data selection.

**Domains touched**
Audit finding capture: `FEAT-AUD-302`.
DefCode master-data selection: `GET /api/psc/masters/psc-def-codes/`, `master_psc_def_code`.

**Decisions**
Accepted default: reuse the existing shared `DefCodeSelect` component and `usePSCDefCodes` hook instead of adding a new audit-specific endpoint.
Accepted default: send the selected `def_code` value through the existing `def_code_id` payload field; the backend continues deriving `def_code` from it when omitted.
Accepted default: keep the modal-level validation message for missing DefCode rather than adding a second inline validation system.
Accepted default: no database schema change.

- `Docs/progress.txt` - Maintain ledger entry appended.
