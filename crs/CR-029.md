**What & why**

Incident PDF Evidence (Documents) is being cleaned so document attachments are not printed as generic numbered labels like "Attachment 1" and "Attachment 2". Each saved document should appear as its own clear document block with the title, description, and file link separated consistently.

**Tier + triggers**

Tier 2 - small behavior/output contract change. Trigger: changed incident PDF layout contract.

**Domains touched**

Step 1 domains touched: Safety incident Phase 4 evidence presentation, incident PDF export.

Mini-interrogation:
- Should evidence upload/storage change? No. Existing Phase 4 evidence rows, metadata, and attachment URLs remain unchanged.
- Should document attachments still print in the PDF? Yes. They should print as separate document blocks rather than numbered attachment rows.
- Should legacy evidence notes and witness notes change? No. Only attachment/document presentation changes.
- Should PDF section selection behavior change? No. Evidence continues to print only when `evidence_documents` is included.

**Decisions**

D-MAINT-CR029 records the current evidence PDF presentation rule.

**Doc cascade**

- `safety_docsuite/APP_FLOW.md` - Incident PDF contract now states each evidence attachment prints as its own document block without numbered attachment labels.

- `safety_docsuite/USER_GUIDE.md` - User PDF guidance now explains that evidence documents print as separate document blocks with Description and File rows.

- `safety_docsuite/BACKEND_STRUCTURE.md` unchanged because no model, schema, endpoint, or storage behavior changed.
- `safety_docsuite/VALIDATION_RULES.md` unchanged because evidence validation did not change.
