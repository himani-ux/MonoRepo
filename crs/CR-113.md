**What & why** - Users need a way to read an already uploaded certificate PDF again when OCR did not fill the certificate fields correctly during the first upload. The change adds a re-read action for the active certificate PDF so the stored file can be processed again without uploading a duplicate version.

**Tier + triggers** - Tier 2. Triggers: new endpoint contract and changed screen state on the certificate detail file panel.

**Domains touched** - Step 1 Certs certificate file handling, OCR processing, tracked-item metadata workflow, audit history, and user-facing certificate detail UI.

**Decisions** - Accepted default: re-read only the active PDF attached to the certificate; reuse the same OCR engine, OCR context rules, confidence thresholds, and auto-accepted field mapping as normal upload; keep the same upload/write permission gate; do not create a new PDF version; audit the re-read and resulting OCR payload. No new decision ID required.

**Doc cascade** - `certs_docsuite/BACKEND_STRUCTURE.md` documents the new re-read endpoint and behavior. `certs_docsuite/APP_FLOW.md` documents the certificate detail file-panel action. `certs_docsuite/USER_GUIDE.md` explains when users should use the action. `certs_docsuite/FIELD_MAP.md` unchanged because no new stored fields are added and existing OCR payload/tracked-item fields are reused.

**Tests** - Backend regression test for the re-read endpoint plus frontend API/route validation tests for the new action. Verified with `python manage.py test apps.certs.tests.CertsAppRegistrationTests apps.certs.tests.TrackedItemPdfReparseViewTests -v 2`, `npm test -- certs.test.ts certs-route-validation.test.ts`, targeted ESLint, `npm run type-check`, and `npm run build`.

**Fidelity check** - no deltas.

**Exemptions** - none.
