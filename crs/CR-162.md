**What & why**
Fix audit workflow gaps found during the Step 5 review: backend plan registration must enforce the same registerable-plan rules as the UI, successful registration must move the source plan out of the registerable pool, first PIC review must persist the audit PIC of record, acknowledged audits must enter closure in progress when NC/OBS closure starts, and audit finding rows must return in deterministic order.

**Tier + triggers**
Tier 2 - changed validation rules and workflow state behavior for existing audit endpoints.

**Domains touched**
Step 1 domains: audit planning/register, audit registration, audit NC/OBS CAR workflow, audit detail response ordering, audit user guidance.

**Decisions**
Accepted default: use existing `master_audit_plan.status = IN_PROGRESS` when an audit is registered from a plan; no migration or new status value.
Accepted default: promote `audit_detail.status` from `VESSEL_ACKNOWLEDGED` to `CLOSURE_IN_PROGRESS` on the first successful audit CAR workflow action after vessel acknowledgement; no new user action or endpoint.
