# CR-105

## What & why
Make the Certs reconciliation "Notify Master" action visible and actionable on the vessel side. Office reviewers need a reliable way to send class-status reconciliation findings to the vessel Master, and ship-side users need a simple place to review what office is asking them to check after a class-status PDF upload.

## Tier + triggers
Tier 2 - small feature / behavior change. Triggers: changed endpoint behavior, new vessel-side API surface, new ship-side screen state, and changed reconciliation notification behavior. No schema migration or dependency change is planned.

## Domains touched
Step 1 domains touched: Certs reconciliation review workflow, ship-side Certs dashboard/review surface, reconciliation API contract, audit logging, backend/frontend regression tests, and Certs documentation.

Mini-interrogation:
- Office behavior: clicking "Notify Master" must create a vessel-visible review item and keep an audit trail.
- Ship-side visibility: Master and authorized vessel Certs users see office-sent reconciliation findings in Certs, without needing raw UUIDs.
- Review handling: ship-side acknowledgement records that the vessel has reviewed the office note; it does not auto-change certificate validity.
- Storage: reuse existing reconciliation flag data where possible; do not add a table unless implementation proves it is necessary.
- Notification channel: the immediate fix is an in-app Certs vessel window; email/Slack/global notification integration remains separate from this CR because the shared `master_notification` schema is currently not compatible with the Certs dispatcher.
- UI: keep the existing design, add only the minimum vessel-side review surface needed.

## Decisions
No new SSOT decision. This implements the existing class-reconciliation alert intent already documented for `Notify Master` and mismatch review.
