# DefIntel Builder Skill (feature-specific)

## Single source of truth
- Always read: `docs/DefIntel_Phasewise_Codex_Prompt.md`
- Treat it as the spec. If a user prompt conflicts, call it out and ask for an explicit override.

## Non-negotiables
1) No guesswork. Every claim must cite repo evidence (paths, symbols, and line refs where possible).
2) Phase gating: execute ONLY the phase the user requests. Do not continue.
3) Data separation: OpenSource must NEVER be inserted into internal inspection/deficiency/CAR tables. OpenSource persists only in DefIntel tables.
4) Template-based Excel export only: checklist export must be generated by loading `docs/templates/Preparation Checklist.xlsx` and writing rows into the template. Do not recreate formatting from scratch.
5) Do not break existing logic: no changes to existing upload validators or existing `/inspections/export-excel/` behavior.

## Allowed changes
- Add new DefIntel models/migrations (only those specified in the MD)
- Add new DefIntel endpoints (only those specified in the MD)
- Implement `/reports` screen (replace placeholder) only when the MD phase requires it
- Add tests required by the MD

## Disallowed changes (unless explicitly in MD)
- Modify existing inspection/CAR workflows
- Alter existing export formats/endpoints
- Expand offline scope beyond what the MD defines

## Required outputs
For each phase completion, output exactly what the MD requires:
- files changed/created
- migrations (if any)
- API contracts (if any)
- manual verification checklist
- performance notes
