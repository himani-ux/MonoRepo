   - Fixed: Corrected response handling in API layer

   BUG #5 — user_type case mismatch (CRITICAL):
   - Backend sends `user_type: 'VESSEL'` (uppercase) in JWT token claims
   - Frontend compares with `'vessel'` (lowercase) in edit page permission checks
   - ALL vessel master permission checks failed (CAR edit, inspection edit, follow-up)
   - Fixed: Added `normalizeUser()` function in `lib/api/auth.ts` to lowercase user_type
   - Applied to both `login` and `me` API responses
   - User reported: "master acts as admin onboard and can make and edit CAR?"

   BUG #5b — CanEditCAR missing REWORK_REQUESTED:
   - `apps/car/permissions.py` CanEditCAR only allowed DRAFT status for vessel master
   - Should also allow REWORK_REQUESTED (as `accounts/permissions.py` version correctly does)
   - Fixed: Added `CARStatus.REWORK_REQUESTED` to allowed statuses tuple

   BUG #6 — parseInt on UUID vessel_id (CRITICAL):
   - `routes/inspections/new.tsx` did `parseInt(user.vessel_id, 10)` on a UUID string
   - UUID like "e2e7ff0d-ab6d-4485-afb8-aa45aa537d73" → parseInt returns NaN
   - Triggered "Unable to determine vessel" error toast
   - Fixed: Removed parseInt, pass string directly
   - Changed CreateInspectionInput.vessel_id type from `number` to `string`
   - Changed createdInspectionId state type from `number | null` to `string | null`
   - User reported: "master cannot create CAR Error unable to determine vessel"

   BUG #7 — Frontend API URL mismatches (CRITICAL):
   - Frontend POSTed to `/inspections/` but backend expects `/inspections/create/`
   - Frontend PUT to `/inspections/{id}/` but backend expects `/inspections/${id}/update/`
   - Frontend DELETE to `/inspections/{id}/` but backend expects `/inspections/${id}/delete/`
   - Results in 405 Method Not Allowed
   - Fixed: Updated all 3 URLs in `lib/api/inspections.ts`
   - Not yet re-tested (deferred to next session)
