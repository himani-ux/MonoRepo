# Audit Module Feedback Notes - 2026-09-02

Status: resolved by the `AUDIT-GAPS-RESOLUTION_2026-09-02` package and Prince's 2026-09-02 rulings. This note records the approved solution direction; implementation status is tracked through CR-179 and the Maintain Mode progress ledger.

## Approved Resolution Mapping

1. **Finding evidence capture - D-AUDRS-140**
   Objective Evidence remains a mandatory typed field. Finding-level attachments must be added as a supplement while the audit is open, using category `FINDING_OBJECTIVE_EVIDENCE`. Accepted evidence file types are photos/images, `.docx`, PDF, and Excel `.xlsx`. Attachments are listed under Part A on NC/OBS PDFs; image embedding is not required for v1.0. The final storage convention remains pending a one-page proposal and confirmation.

2. **Audit DefCode source separation - D-AUDRS-141**
   Audit findings must not expose PSC DefCode or Action Code input. Legacy `psc_deficiency` bridge columns for audit rows use sentinel DefCode `00000` and a null Action Code. The live def-code master/table shape must be confirmed before implementation, because production table shape is still an identified residual risk.

3. **Finding target date - D-AUDRS-141**
   The closure deadline belongs on the finding header at creation time. It is pre-filled from the finding category rule and remains editable at raise time up to a maximum of 90 days. Later changes are handled only through a Lead Auditor closure-deadline extension under D-AUDRS-146; Part D/OBS Part B action-plan dates remain separate corrective-action dates.

4. **Audit CAR number series - D-AUDRS-142**
   Audit CAR numbers use `{SCOPE}-AUDIT-{YYYY}-{NNN}` with a three-digit yearly sequence. Vessel audits use the vessel code, for example `EAT-AUDIT-2026-001`; office audits use `KSM-AUDIT-2026-001`. The generator must read `inspection_type`; hard-coded `PSC` must not appear in Audit CAR numbers. The separate PSC vessel-code numbering change under CR-134 remains valid for PSC CARs.

5. **NC and OBS workflow differentiation - D-AUDRS-145 / D-AUDRS-146**
   There is one configured presentation per finding type. NC closure uses the dense form only; the `/audit/findings/:id/nc/wizard` route is withdrawn. Observation closure uses the wizard only; no dense OBS form should be mounted and the user must not choose between dense and wizard modes. Observation drafting is vessel-only, with no office draft step.

6. **NC root-cause classification - D-AUDRS-145**
   The NC root-cause section uses the PSC CAR engine's CLC selection table, `CLC_Category` / `CLC_Item`, persisted through `psc_car_clc_mapping`, plus a root-cause summary with the existing minimum-length rule. The previous RCA Method / 5-Why / Fishbone / eight-category form elements are removed from the Audit NC closure form.

7. **Certificates at Risk de-duplication**
   `certificates_at_risk` is captured once on the finding modal. Duplicate editable controls in Parts E and F are removed. Downstream forms and PDFs display the captured Part A value as context only. The separate `certificate_impact` modal field is dropped to avoid collecting the same concept twice.

8. **Part G and attribution - D-AUDRS-143 / D-AUDRS-146 / D-AUDRS-148**
   Manual signer/author entry is removed where the actor is known from workflow context. For internal NCs, Part F is PIC acceptance/return, Part G is Lead Auditor verification and close, and Part E is Superintendent effectiveness review at the next inspection. Attribution is captured server-side from the authenticated login and the in-system action is the digital signature. External audit findings remain manual where D-204/D-244 require manual external authority data.

9. **Audit navigation consolidation - D-084 refinement**
   The Audit area keeps a single top-level Audit navigation entry with Vessel Internal, Office Internal, and External list sub-tabs. A single Register Audit action opens an Internal / External chooser, gate-filtered by permissions. Internal opens the internal audit registration path; External opens `/audit/external/new`, including office DOC external audits.

10. **OPM F 713 extension display and generation - D-AUDRS-144 / D-AUDRS-149**
    OPM F 713 is generated by VIMS from the extension request; users do not upload a signed OPM F 713. DPA approval in VIMS is the signature and the generated PDF includes approver identity, date-time, D-261 QR payload, and SHA-256 hash. The register column should render form-specific readable text, such as approved-to date, sought/approved dates, and Part B audit completion details, using platform date formatting rather than raw ISO strings. `OPM-F-713-{YYYY}-{NNN}` remains the system reference but is secondary on screen because the source form has no reference-number field.

## Closure Workflow Rulings

- **NC internal workflow - D-AUDRS-146:** Vessel submits the NC closure response, PIC accepts or returns it with a mandatory comment, Lead Auditor verifies and closes by document review, and Superintendent completes Part E at the next inspection through the Superintendent Inspection linkage.
- **Observation workflow - D-AUDRS-145 / D-AUDRS-146:** Vessel completes the OBS wizard. PIC acceptance can return the observation to the vessel for rework; accepted observations proceed to Lead Auditor audit-trail verification where applicable.
- **Cross-module effectiveness - D-AUDRS-147:** At `LEAD_AUDITOR_CLOSED`, Audit creates the same `psc_physical_verification` row pattern used by PSC CAR closure. The Superintendent Inspection module picks it up on the next visit and writes the effectiveness outcome back to Part E.
- **Digital signatures - D-AUDRS-148:** All audit form signatures are in-system actions by authenticated users. No Master, PIC, Lead Auditor, Superintendent, or DPA prints, wet-ink signs, scans back, or uploads signed forms. Generated PDFs render the signature event and D-261 QR/hash footer.
