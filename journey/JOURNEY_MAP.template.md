# JOURNEY_MAP — canonical INTENT SSOT

This file holds journey **intent** only. `JOURNEY_MAP.md` is the single source
of truth for authoring intent — it is NOT the runtime-status store.

Runtime truth (`ci_status`, `last_run`, `ci_run_id`, `ci_artifact`,
`failure_summary`) is **not** stored here — it lives exclusively in the
CI-owned ledger (`JOURNEY_STATUS.json`). No agent or human writes runtime
fields into this file; `check-journey-authority.sh` rejects any such attempt.

## Field ownership

| Field | Owner |
|---|---|
| persona, goal, priority | Step 1 / Reality engine, human-confirmed |
| origin, evidence | capture engine (PERSONA origin: evidence may be empty) |
| steps, oracle, oracle_surface, negative_states, data_fixtures | journey-spec author (intent), human-confirmed |
| test | test author (`src/`-blind — maps intent to a runnable spec path) |
| runner | TECH_STACK |
| author_status | authoring agent / human |
| preconditions (optional) | owner: journey-spec author; consumer: UAT preflight gate |
| oracle_classes (optional) | owner: journey-spec author; consumer: `check-uat-oracle-scope.sh` (browser-UAT oracle-scope gate) |
| extraction_provenance (optional) | owner: `journey-extracted-confirm.sh` (confirm gate, EXTRACTED origin only); consumer: audit |
| **runtime truth** (ci_status, last_run, ci_run_id, ci_artifact, failure_summary) | **CI only — no agent/human write path; lives in JOURNEY_STATUS.json** |

## Required fields

`origin, persona, goal, priority, covers, oracle_surface, negative_states,
steps, oracle, evidence, test, runner, author_status`.

Optional but encouraged: `flows`, `data_fixtures`, `exemptions`.
`data_fixtures` is required when the journey uses external or user-supplied data.

`preconditions` is optional (not in the required-fields list above). When
present it is a block field like `steps`: the `preconditions:` line followed
by one or more indented entries of the form `  - <kind>: <value>`, where
`kind ∈ {auth, env, data, state}` and `value` matches `^[A-Za-z0-9._/-]+$`
(non-empty, no spaces):
- `auth` — named auth context the run needs
- `env` — environment variable that must be set at UAT preflight time
- `data` — named data/fixture state (e.g. DB rows) verified by probe at preflight
- `state` — named app state verified by probe at preflight

`lint-journey-map.sh` (Check 8) validates this grammar only — it does not
check that the referenced auth/env/data/state actually exists; that is the
job of a later UAT preflight gate.

`oracle_classes` is optional (not in the required-fields list above, spec
G4). When present it is a single-line field like `oracle`: the value is
class tokens joined by the literal separator ` AND `, POSITIONALLY matching
this journey's own `oracle:` clauses (which are themselves joined by the
same literal ` AND ` — see the `oracle:` field and the example below).
Token grammar: `token ∈ {browser, lower}`:
- `browser` — this oracle clause is adjudicable from the browser/UI surface
  a UAT pass drives.
- `lower` — this oracle clause is verified below the UI (unit/integration
  tests) — a browser UAT must not report its absence as a gap.

`lint-journey-map.sh` (Check 9) validates this grammar only: token
membership in `{browser, lower}`, and that splitting `oracle:` and
`oracle_classes:` both on literal ` AND ` yields the same clause count. It
does not adjudicate any claim against these classes — that is the job of
`journey/bin/check-uat-oracle-scope.sh`, which rejects a browser-UAT
`[C-absent]` claim asserting a `lower`-classed clause as a gap.
**Generation pipelines do not emit this field in v1** — `oracle_classes` is
authored by the journey-spec author (human-confirmed), same as `oracle`
itself; it is never machine-generated by `journey/gen/`.

`extraction_provenance` is optional (not in the required-fields list above,
spec §14 Q1). It appears ONLY on a promoted `origin: EXTRACTED` block, and
is written exclusively by `journey/bin/journey-extracted-confirm.sh` (the
human confirmation gate, task E5) at the moment of promotion — never
authored by hand. Grammar: a single-line field like `oracle`, value shaped
`<EXTRACTED-id> commit:<40-hex> confirmed:<12-hex>`:
- `<EXTRACTED-id>` — the staging entry (`EXTRACTED-<n>`, from
  `JOURNEY_EXTRACTED.md`) this block was promoted from.
- `commit:<40-hex>` — the pinned `extraction_commit` the staging file's
  citations were verified against.
- `confirmed:<12-hex>` — the first 12 hex characters of the sha256 of the
  staging file's bytes at the moment of promotion — an audit stamp, not a
  runtime-truth field (it never changes after promotion and carries no
  claim about test execution).

`lint-journey-map.sh` (Check 10) validates this grammar only, when the
field is present — it is an audit trail for a human or a later gate to
trace a promoted journey back to the exact staging content and commit it
came from, never a claim that the journey has been validated at runtime.

Allowed enum values:
- `origin ∈ {PERSONA, SIMULATOR, REALITY, EXTRACTED, DERIVED}` (DERIVED = generated from canonical docs)
- `oracle_surface ∈ {UI, API, UI+API}`
- `author_status ∈ {UNWRITTEN, WRITTEN, EXEMPT}`

## Example (delete when seeding a real project)

## JOURNEY-000 — "Example: corrected upload after rejection"
origin:          PERSONA
persona:         P2 (impatient ops user)
goal:            upload a corrected file after the first was rejected, and see it accepted
priority:        P0
covers:          FEAT-000
flows:           AF-0
oracle_surface:  UI+API
negative_states: schema_error, retry_upload
data_fixtures:   malformed.csv, corrected.csv
preconditions:
  - env: UAT_BASE_URL
steps:
  1. land on /invoices (state: AUTHENTICATED, EMPTY)
  2. upload malformed.csv → inject schema_error
  3. re-upload corrected.csv
  4. observe retry_upload → ACCEPTED
oracle:          row status=ACCEPTED AND GET /invoices returns the row
oracle_classes:  browser AND lower
evidence:        []
test:            tests/journeys/journey-000.spec.ts
runner:          playwright
author_status:   WRITTEN
exemptions:      []
